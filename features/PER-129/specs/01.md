## Schema and API Contracts

### Database Schema

Five tables created on startup if missing, foreign keys enabled:

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS product (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  author TEXT NOT NULL,
  price REAL NOT NULL,
  stock INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS cart (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS cart_item (
  cart_id INTEGER NOT NULL,
  book_id INTEGER NOT NULL,
  quantity INTEGER NOT NULL,
  PRIMARY KEY (cart_id, book_id),
  FOREIGN KEY (cart_id) REFERENCES cart(id) ON DELETE CASCADE,
  FOREIGN KEY (book_id) REFERENCES product(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS "order" (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  status TEXT NOT NULL DEFAULT 'placed',
  total REAL NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS order_item (
  order_id INTEGER NOT NULL,
  book_id INTEGER NOT NULL,
  quantity INTEGER NOT NULL,
  price REAL NOT NULL,
  PRIMARY KEY (order_id, book_id),
  FOREIGN KEY (order_id) REFERENCES "order"(id) ON DELETE CASCADE
);
```

**Constraints:**
- `cart_item` and `order_item` use composite primary keys to prevent duplicate (cart, book) or (order, book) rows.
- `order_item.book_id` is NOT a foreign key (allows orders to persist after book deletion from catalog).
- `product.stock` and all quantity/price fields must be non-negative (enforced in application logic, not database constraints).

### API Routes

All routes return JSON. All errors return `{ "error": "<message>" }` with appropriate HTTP status (400 validation, 403 auth, 404 not found, 500 internal).

#### Health Check

**`GET /api/health`**
- **Request:** None
- **Response:** `200 { "status": "ok" }`

---

#### Catalog (Books)

**`POST /api/books`** (Admin only)
- **Request Headers:** `x-role: admin`
- **Request Body:** `{ "title": "<string>", "author": "<string>", "price": <number>, "stock": <number> }`
- **Response (201):** `{ "id": <number>, "title": "<string>", "author": "<string>", "price": <number>, "stock": <number> }`
- **Response (403):** `{ "error": "Admin role required" }`
- **Response (400):** `{ "error": "<validation message>" }` (if title/author empty, price ≤ 0, stock < 0)

**`GET /api/books`**
- **Response (200):** `[{ "id": <number>, "title": "<string>", "author": "<string>", "price": <number>, "stock": <number> }, ...]`

**`GET /api/books/:id`**
- **Response (200):** `{ "id": <number>, "title": "<string>", "author": "<string>", "price": <number>, "stock": <number> }`
- **Response (404):** `{ "error": "Book not found" }`

---

#### Cart

**`POST /api/cart/items`**
- **Request Headers:** `x-cart-id: <number>` (optional; if missing, creates new cart and returns cart ID)
- **Request Body:** `{ "bookId": <number>, "quantity": <number> }`
- **Response (201):** `{ "cartId": <number>, "bookId": <number>, "quantity": <number> }`
- **Response (400):** `{ "error": "<message>" }` (quantity ≤ 0, quantity exceeds stock, or total cart quantity for that book exceeds stock)
- **Response (404):** `{ "error": "Book not found" }`
- **Behavior:** If book already in cart, increments quantity by request amount (still validating against stock). Otherwise inserts new cart_item row.

**`GET /api/cart`**
- **Request Headers:** `x-cart-id: <number>` (required)
- **Response (200):** `{ "cartId": <number>, "items": [{ "bookId": <number>, "title": "<string>", "author": "<string>", "quantity": <number>, "price": <number>, "lineTotal": <number> }, ...] }`
- **Response (400):** `{ "error": "Cart ID required" }` (if x-cart-id missing)
- **Response (404):** `{ "error": "Cart not found" }` (if cart_id does not exist)
- **Behavior:** Joins cart_item with product to get current price and book details; calculates lineTotal as quantity × price.

**`DELETE /api/cart/items/:bookId`**
- **Request Headers:** `x-cart-id: <number>` (required)
- **Response (200):** `{ "message": "Item removed" }`
- **Response (400):** `{ "error": "Cart ID required" }`
- **Response (404):** `{ "error": "Item not found in cart" }` (if cart_item row does not exist)

---

#### Checkout

**`POST /api/checkout`**
- **Request Headers:** `x-cart-id: <number>` (required)
- **Response (201):** `{ "id": <number>, "status": "placed", "items": [{ "bookId": <number>, "quantity": <number>, "price": <number> }, ...], "total": <number>, "createdAt": "<ISO 8601 timestamp>" }`
- **Response (400):** `{ "error": "<message>" }` (cart empty, cart not found, or any cart_item.quantity > product.stock)
- **Response (404):** `{ "error": "Cart not found" }`
- **Transaction steps:**
  1. SELECT all cart_item rows for cart_id, JOIN product to get current stock and price.
  2. Validate every quantity ≤ stock; if any fails, rollback and return 400.
  3. Calculate total as sum of (quantity × price) for all lines.
  4. INSERT order row with status "placed", total, created_at.
  5. INSERT order_item rows copying book_id, quantity, and current price from product.
  6. UPDATE product SET stock = stock - quantity for each book in cart.
  7. DELETE all cart_item rows for that cart_id.
  8. COMMIT and return order.

---

#### Orders

**`POST /api/orders/:id/ship`** (Admin only)
- **Request Headers:** `x-role: admin`
- **Response (200):** `{ "id": <number>, "status": "shipped", "total": <number>, "createdAt": "<ISO 8601 timestamp>" }`
- **Response (403):** `{ "error": "Admin role required" }`
- **Response (404):** `{ "error": "Order not found" }`
- **Behavior:** UPDATE order SET status = "shipped" WHERE id = :id.

## Risks and Mitigations

### R-1: Stock oversell due to concurrent checkouts
**Risk:** Two simultaneous POST /api/checkout requests could both read stock = 5, both validate quantity = 3, both succeed, reducing stock to -1.  
**Mitigation:** SQLite's default serialized mode (better-sqlite3 default) ensures one write transaction at a time. The transaction in checkout locks the product table for update; the second checkout waits for the first to commit, then reads the reduced stock and fails validation if quantity exceeds new stock. **No application-level locking required.**  
**Impact:** Low — single-process SQLite serialized mode is sufficient.

### R-2: Cart ID guessing / cart hijacking
**Risk:** Shopper guesses another cart ID and modifies someone else's cart.  
**Mitigation:** **Accepted risk.** Requirements explicitly exclude user accounts and sessions. Cart IDs are auto-incremented integers; guessing is impractical for a demo. No cart ownership mechanism is in scope.  
**Impact:** Low for demo purposes; would require authentication in production.

### R-3: Price changes between add-to-cart and checkout
**Risk:** Book price changes after shopper adds to cart but before checkout.  
**Mitigation:** By design, order_item.price captures the price **at checkout time** (current product.price), not the price when added to cart. GET /api/cart shows current price (which may differ from when item was added). This is intentional — no price lock is required.  
**Impact:** None — expected behavior per schema design.

### R-4: Negative stock or price input
**Risk:** Admin submits negative stock or price via POST /api/books.  
**Mitigation:** Application validates price > 0 and stock ≥ 0 in src/routes/books.js; return 400 if validation fails. No database CHECK constraint.  
**Impact:** Low — validation in route handler prevents bad data.

### R-5: Database file corruption or loss
**Risk:** SQLite file deleted or corrupted.  
**Mitigation:** **Accepted risk.** No backup, replication, or durability mechanism required per acceptance criteria. AC-14 tests persistence across restart, not file loss.  
**Impact:** Low for demo; would require backup strategy in production.

### R-6: Foreign key constraint violations
**Risk:** Deleting a book from catalog while it exists in a cart or order.  
**Mitigation:** cart_item has ON DELETE CASCADE foreign key to product — deleting a book removes it from all carts. order_item.book_id is NOT a foreign key (stored as integer) — orders persist even if book is deleted from catalog.  
**Impact:** Low — design choice per schema; orders keep book_id for historical records.

### R-7: Cart expiration / abandoned carts
**Risk:** Carts accumulate in database, never cleaned up.  
**Mitigation:** **Deferred.** No TTL or cleanup mechanism in scope. Carts persist indefinitely unless manually deleted.  
**Impact:** Low for demo; would require scheduled cleanup in production.

### R-8: Missing x-cart-id or x-role headers
**Risk:** Client forgets to send required headers.  
**Mitigation:** Middleware and route handlers return 400 "Cart ID required" or 403 "Admin role required" when headers are missing or invalid.  
**Impact:** Low — clear error messages guide correct usage.
